# Go standards

## Layout

- Put each binary's entry point in `cmd/<binary>/main.go` and keep it to wiring: flags, config, dependencies, server start.
- Put component logic in `internal/<component>/`, one package per component named for what it does.
- Promote a type to a named shared package under `internal/` only when a second component imports it.
- Do not create a package named `util`, `utils`, `common`, `helpers`, `shared`, or `models`.
- Keep imports flowing from `cmd` to a component to shared packages. Never import one component from another.
- Do not add a `pkg/` directory. Nothing in this module is meant for outside importers.

## Naming

- Use short lowercase package names with no underscores or mixed caps.
- Do not repeat the package name in an exported identifier. Write `central.NewRouter`, not `central.NewCentralRouter`.
- Use `MixedCaps` for exported names and `mixedCaps` for unexported ones. Keep initialisms in one case (`plateID`, `HTTPClient`).
- Give every exported identifier a doc comment that starts with its name.
- Name interfaces for the behavior they describe and define them in the package that consumes them.

## Errors

- Return `error` as the last result and check it at the call site. Never discard an error with `_` outside a deferred close.
- Wrap an error with context using `fmt.Errorf("...: %w", err)`.
- Compare errors with `errors.Is` and `errors.As`. Never compare error strings.
- Declare sentinel errors as `var ErrX = errors.New(...)` in the package that returns them.
- Do not `panic` for an expected failure. Reserve it for a programmer error at startup.
- Log an error or return it, never both.

## Context and concurrency

- Take `context.Context` as the first parameter of any function that does I/O or can block, named `ctx`.
- Never store a context in a struct field.
- Pass the request context through every database and HTTP call a handler makes.
- Give every goroutine an owner that can stop it and waits for it to exit.
- Protect shared state with a mutex or a single owning goroutine. Do not share a map across goroutines without one.

## HTTP

- Use `net/http` with `http.ServeMux` method and path patterns (`"GET /washes/{id}"`). Do not add a router framework.
- Set `ReadHeaderTimeout` on every `http.Server`, and a timeout on every outbound `http.Client`.
- Return a router constructor from the component package so tests drive it through `httptest`.
- Decode request bodies into a typed struct and validate it before use.

## Database

- Use `database/sql` with explicit queries. Do not add an ORM.
- Apply `.claude/rules/canon/lib/370-database.md` to every query, migration, and transaction in Go.
- Use the `Context` variant of every call (`QueryContext`, `ExecContext`, `BeginTx`).
- Close every `*sql.Rows` with `defer rows.Close()` and check `rows.Err()` after the loop.
- Apply `.claude/rules/canon/lib/360-security-server.md` to every handler that takes outside input.

## Logging

- Log through `log/slog` with key-value attributes. Do not use `log.Printf` or `fmt.Println` in services.

## Tooling

- Run `bun run lint:fix`, `bun run typecheck`, and `bun run test:run` from `core/` before committing.
- Treat every `golangci-lint` finding as a failure. Do not add a `//nolint` directive without a reason on the same line.
